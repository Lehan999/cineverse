# Cineverse data sources and storage rules

Last checked: 2026-11-06. Cineverse is a non-commercial student project. These notes are engineering guidance, not a substitute for confirming terms before a public/commercial launch.

## Current local catalog

The repeatable bootstrap seeds 11 identities: four Telugu, four Hindi and three English films. Each row links to a Wikidata item. The exact title/year/language values are a small seed, not evidence of broad coverage. Editorial genre and mood tags are explicitly marked as Cineverse-curated; they are not movie-provider facts. Poster art is now locally cached for all 11 seed titles; plots, cast, streaming availability and third-party ratings remain unavailable unless sourced. Eleven other catalog records currently have no poster image from their TMDB detail records. The site uses designed fallback artwork instead of inventing movie posters.

## 45-title coverage check status

`tests/test_catalog_coverage.py` exercises title normalization and duplicate-title disambiguation against a 45-title Telugu/Hindi/English test set. It measures the local matching algorithm, **not** provider resolution. The 11 production seed records cover only part of that list. No 45-item live OMDb/Wikidata retrieval run was possible because there is no OMDb key and Python internet access to the APIs is unavailable. Title/year/language/synopsis/cast/art/rating field completeness is not represented as a pass. See `IMPLEMENTATION_REPORT.md` for exact automated test results and this limitation.

## Safe provider operating policy

Provider adapters run only from controlled maintenance work, never on page rendering. Keep keys in the server environment, bound requests with timeouts, do not log credentials, save explicit source/license/fetched-at provenance, and set source-specific retention before enabling persistent caching. Missing values remain null. A source outage must not remove local movie records or prevent accounts, first-party reviews, lists, or offline discovery from working.
